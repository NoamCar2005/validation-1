# Backend Pipeline Design

## Overview

This document describes the content generation backend for Validation 1. The original N8N workflow has been replaced with a Supabase Edge Function pipeline that runs entirely in-app. The frontend is unchanged — it still calls the same `generate-content` edge function and reads the same response shape.

---

## Pipeline Flow

```
Frontend (loading page)
  └─ POST /functions/v1/generate-content { user_id }
       │
       ▼
generate-content/index.ts          ← thin orchestrator
  1. Fetch user.website_url + survey_answers from Supabase DB
  2. Call pipeline(website_url, survey_answers, user_id)
  3. Return { posts: [...] } to frontend
       │
       ▼
_shared/pipeline.ts                ← stage orchestrator
  Stage 1: scrape(website_url)
  Stage 2: summarize(scraped_text, survey_answers)
  Stage 3: plan(business_profile)
  Stage 4: Promise.all([
             generatePost('value', profile, plan.value_post),
             generatePost('trust', profile, plan.trust_post),
             generatePost('cta',   profile, plan.cta_post),
           ])
           └─ each generatePost also calls generateImage internally
  Stage 5: Insert 3 posts to Supabase DB (posts table)
  Return: posts[]
```

**All 3 posts (copy + image) are generated in parallel in Stage 4.** Stages 1–3 are sequential since each depends on the previous output.

---

## File Structure & Responsibilities

```
supabase/functions/
  generate-content/
    index.ts              ← Entry point. Reads user/survey from DB, calls pipeline, returns response.
                            Do NOT put business logic here.

  _shared/
    types.ts              ← All TypeScript interfaces: BusinessProfile, PostPlan, Post, etc.
    pipeline.ts           ← Orchestrates all stages in order. The only file that writes to Supabase DB.
    scrape.ts             ← Fetches website via Jina Reader (r.jina.ai). Returns clean markdown text.
    summarize.ts          ← Agent 1: Gemini text call. Converts scraped text + survey → BusinessProfile JSON.
    plan.ts               ← Agent 2: Gemini text call. Converts BusinessProfile → 3-post MarketingPlan JSON.
    generate-post.ts      ← Agent 3: Gemini text call. Converts profile + post plan → {content, copy, channel}.
                            Also calls generateImage internally.
    generate-image.ts     ← Agent 4: Gemini image call. Converts image prompt → image bytes → Supabase Storage URL.
```

## Agents: Where They Live, What They Do, Where to Change Prompts

### Agent 1 — Summarize Agent
**File:** `supabase/functions/_shared/summarize.ts`
**Model:** `gemini-3-flash`
**Input:** Raw website text (markdown) + survey answers array
**Output:** `BusinessProfile` JSON — business name, type, niche, target audience, core offer, tone, pain points, survey insights
**System prompt location:** Inside `summarize.ts`, exported as `SUMMARIZE_SYSTEM_PROMPT` constant at the top of the file
**To change:** Edit the `SUMMARIZE_SYSTEM_PROMPT` string in that file

### Agent 2 — Plan Agent
**File:** `supabase/functions/_shared/plan.ts`
**Model:** `gemini-3-flash`
**Input:** `BusinessProfile` JSON
**Output:** `MarketingPlan` JSON — 3 post plans (value, trust, cta), each with angle, key_message, hook (Hebrew), tone, image_direction
**System prompt location:** Inside `plan.ts`, exported as `PLAN_SYSTEM_PROMPT` constant at the top of the file
**To change:** Edit the `PLAN_SYSTEM_PROMPT` string in that file

### Agent 3 — Copywriter Agent (×3, runs in parallel)
**File:** `supabase/functions/_shared/generate-post.ts`
**Model:** `gemini-3-flash`
**Input:** `BusinessProfile` + one `PostPlan` (value | trust | cta) + post_type string
**Output:** `{ content: string, copy: string, channel_recommended: string, image_prompt: string }`
**System prompt location:** Inside `generate-post.ts` — three separate prompt constants at the top:
  - `VALUE_POST_SYSTEM_PROMPT`
  - `TRUST_POST_SYSTEM_PROMPT`
  - `CTA_POST_SYSTEM_PROMPT`
**To change:** Edit the relevant constant. Each constant includes the post's personality, rules, and output format.

### Agent 4 — Image Generation Agent (×3, runs in parallel with Agent 3)
**File:** `supabase/functions/_shared/generate-image.ts`
**Model:** `google/nano-banana-pro`
**Input:** Image prompt string (English, generated by Agent 3) + channel (for aspect ratio) + post_type
**Output:** Public Supabase Storage URL (`Validation/{user_id}/{post_type}.png`)
**No system prompt** — image model takes a single text prompt
**To change prompt format:** Edit the `buildImagePrompt()` function in `generate-image.ts`
**Hebrew text in images:** Supported by this model. Agent 3's image prompt may include Hebrew text instructions when appropriate.

## Data Flow & Storage

### Supabase Database Tables

**`users`** — written by frontend on URL submit
- `id`, `website_url`, `email`, `survey_completed`, `whatsapp_opted_in`, `created_at`

**`survey_responses`** — written by frontend after survey
- `id`, `user_id`, `question_key`, `answer_text`, `answer_value`, `created_at`

**`posts`** — written by `pipeline.ts` after generation completes
- `id`, `user_id`, `post_type` (value|trust|cta), `content`, `copy`, `image_url`, `channel_recommended`, `copied_count`, `generated_at`

### Supabase Storage

**Bucket:** `Validation` (must exist and be public)
**Path pattern:** `Validation/{user_id}/{post_type}.png`
- e.g. `Validation/abc-123/value.png`
- e.g. `Validation/abc-123/trust.png`
- e.g. `Validation/abc-123/cta.png`

Public URL format: `{SUPABASE_URL}/storage/v1/object/public/Validation/{user_id}/{post_type}.png`

## Error Handling

| Stage | On Failure |
|---|---|
| Scrape | Returns 422 + Hebrew error: "לא הצלחנו לסרוק את האתר שלך" |
| Summarize | Returns 500 + Hebrew error: "שגיאה בניתוח האתר" — retries once |
| Plan | Returns 500 + Hebrew error: "שגיאה בתכנון התוכן" — retries once |
| Generate post copy | Skips that post (other 2 still complete) |
| Generate image | Sets `image_url: null`, post still saves and returns |
| < 2 posts generated | Returns 500 + Hebrew error: "שגיאה ביצירת התוכן. אנא נסה שוב." |

## Timing Budget

| Stage | Expected |
|---|---|
| Jina scrape | ~3s |
| Summarize (Gemini) | ~4s |
| Plan (Gemini) | ~5s |
| 3× copy + 3× image (parallel) | ~20-30s |
| DB write + read | ~1s |
| **Total** | **~35-45s** |

Supabase Edge Function wall clock limit: 150s. We're well within budget.

## How to Swap the Image Model

The image model is isolated in one file: `supabase/functions/_shared/generate-image.ts`

To swap:
1. Change the `IMAGE_MODEL` constant at the top of the file
2. Update the `callImageAPI()` function body if the new model has a different request/response shape
3. Update `parseImageResponse()` to extract the image bytes/URL from the new response format

Everything else (pipeline, post generation, storage upload) is unchanged.
